## Finding 1: OU Parameter-Calibrated Entry/Exit for R29 Pairs Trading
**Source**: arXiv:2604.02035 — "Reinforcement Learning for Speculative Trading under Exploratory Framework" (Yun Zhao, Alex S.L. Tse, Harry Zheng)

### What the Paper Shows
The paper formulates pairs trading entry/exit as a sequential optimal stopping problem over an OU spread process. Key contributions:
- Models spread S(t) as an Ornstein-Uhlenbeck process: dS = θ(μ-S)dt + σdW
- Entry/exit stopping times parameterized as Cox process intensities (continuous probability of acting)
- Introduces Shannon entropy regularization for exploration (learns a distribution over actions)
- Derives **closed-form Gibbs distribution** for the optimal entry/exit intensity policy

### Key Economic Insight on Thresholds
The paper shows that optimal threshold behavior follows from OU parameter values:
- θ = mean reversion speed (how quickly spread reverts to mean)
- σ = spread volatility
- σ_eq = σ/√(2θ) = the long-run equilibrium standard deviation of the spread (the "natural" 1σ unit)
- Optimal entry threshold is a function of σ_eq, NOT just raw spread volatility

**Why fixed ±2σ is suboptimal:**
- If θ is high (say 0.5/day, half-life ~1.4 days), the spread reverts quickly. A ±2σ threshold is too wide — by the time spread hits ±2σ, it's almost reverting anyway. Better entry at ±1.5σ captures more trades with shorter holding periods.
- If θ is low (say 0.05/day, half-life ~14 days), spread can stay wide for 2+ weeks. Entry at ±2σ requires long hold; ±2.5σ provides better expected profit per trade and lower false-positive rate.
- σ/√(2θ) is the natural normalization: optimal threshold ≈ c × σ/√(2θ) for some constant c determined by transaction costs and risk aversion.

### Practical Implementation for R29

```python
import numpy as np
from scipy.optimize import minimize

def fit_ou_params(spread_series):
    """Maximum likelihood estimation of OU parameters."""
    dt = 1.0  # daily
    n = len(spread_series)
    # OLS on discretized OU: S(t+1) = S(t)*e^(-theta*dt) + mu*(1-e^(-theta*dt)) + noise
    x = spread_series[:-1]
    y = spread_series[1:]
    # Closed-form MLE (equivalent to AR(1) regression)
    sx = np.sum(x); sy = np.sum(y); sxx = np.sum(x**2)
    sxy = np.sum(x*y); syy = np.sum(y**2)
    n_obs = len(x)
    mu = (sy*sxx - sx*sxy) / (n_obs*(sxx-sxy) - (sx**2-sx*sy))  # approx
    phi = (sxy - mu*(sx+sy) + n_obs*mu**2) / (sxx - 2*mu*sx + n_obs*mu**2)
    theta = -np.log(np.clip(phi, 1e-6, 0.999)) / dt
    sigma2 = (syy - 2*phi*sxy + phi**2*sxx - 2*mu*(1-phi)*(sy - phi*sx) + n_obs*mu**2*(1-phi)**2) / n_obs
    sigma = np.sqrt(max(sigma2, 1e-8) / dt)
    return theta, sigma, mu

def compute_dynamic_threshold(theta, sigma, base_c=2.0, tc_factor=0.001):
    """Compute dynamic entry threshold based on OU parameters."""
    sigma_eq = sigma / np.sqrt(2 * theta)  # equilibrium std dev
    # Adjust: high theta (fast reversion) → tighter threshold; low theta → wider
    # Half-life = ln(2)/theta
    half_life = np.log(2) / theta
    if half_life < 3:    # fast-reverting: < 3 day half-life
        entry_z = 1.5
    elif half_life < 7:  # medium: 3-7 day half-life
        entry_z = 2.0
    else:                # slow: > 7 day half-life
        entry_z = 2.5
    return entry_z, sigma_eq

# Usage in R29 pairs loop:
# For each pair: theta, sigma, mu = fit_ou_params(spread_60d)
# entry_z, sigma_eq = compute_dynamic_threshold(theta, sigma)
# If spread > mu + entry_z*sigma_eq: short spread (short A, long B)
# If spread < mu - entry_z*sigma_eq: long spread (long A, short B)
# Exit when |spread - mu| < 0.5*sigma_eq (tighter for fast pairs)
```

### Expected R29 Improvement
- Faster pairs (θ > 0.3) get more trades with tighter entries = higher turnover, lower per-trade profit needed
- Slower pairs (θ < 0.1) get fewer but higher-conviction entries
- This replaces the one-size-fits-all ±2σ / 0-exit rule with economically grounded per-pair calibration
- No added cost: OU MLE is ~0.5ms per pair, can be run on 60-day lookback each week

## Finding 2: Anonymization Destroys Transcript Signal for R31
**Source**: arXiv:2511.15364 — "Anonymization and Information Loss" (Wu, Yang, Ying)

### What the Paper Shows
Tested NLP sentiment extraction on earnings call transcripts under three conditions:
1. Original transcript (no modification)
2. Anonymized transcript (company names, numbers, specific products stripped)
3. Look-ahead contaminated transcript (future data accidentally included)

**Key finding**: Anonymization causes WORSE signal degradation than look-ahead bias. Company names, numeric data, and firm-specific language are NOT noise — they ARE the signal-carrying tokens that FinBERT processes most productively.

### Why This Matters for R31
When building R31 text-based PEAD:
- EDGAR transcripts are public domain (Safe Harbor disclosure, quarterly)
- There is NO privacy reason to anonymize
- But many tutorial pipelines preprocess by removing company names (to "prevent data leakage")
- This preprocessing DESTROYS the signal

### Implementation Rule
**DO**: Use raw EDGAR transcripts with FinBERT/Longformer exactly as-is
**DON'T**:
- Remove company names ("Apple", "NVIDIA")
- Replace dollar amounts with [NUMBER]
- Strip product/segment/geography names ("iPhone", "Data Center", "China")
- Remove analyst names from Q&A section

These are exactly the tokens that carry forward-looking performance signals. Keep them.

## Finding 3: Markov Clustered Efficient Frontier for R35
**Source**: arXiv:2604.03946 — "Asset allocation using a Markov process of clustered efficient frontier coefficients states" (Alexander et al.)

### What the Paper Shows
Novel regime detection framework:
1. Estimate rolling efficient frontier for a multi-asset portfolio
2. Decompose EF into 3 coefficients (of square-root quadratic polynomial)
3. Apply hierarchical clustering to coefficient vectors → K distinct market states
4. Model state transitions as first-order Markov chain
5. For each state, compute optimal tangency portfolio
6. Combine via Markov transition probabilities for current state

**Why it's different from Wasserstein HMM**:
- Wasserstein HMM: detects regimes from RETURN DISTRIBUTION changes (probabilistic)
- EF clustering: detects regimes from HOW THE MEAN-VARIANCE FRONTIER SHIFTS (structural)
- EF regime changes when correlations and Sharpe ratios across assets change simultaneously
- Captures more portfolio-relevant regime information than return-level HMM

### R35 Application
The method outperforms static benchmarks significantly and has reproducible code. Could be used as:
1. A complement to Wasserstein HMM: EF regime + return distribution regime = dual confirmation
2. Alternative approach: run EF clustering on current strategy portfolio (PEAD, Div Raise, Pairs, Put-write) to detect when the combined portfolio's efficient frontier degrades
3. Cheaper than Wasserstein HMM for implementation — only needs portfolio return series and scipy clustering

GitHub: https://github.com/nolanalexander/efficient-frontier-coefficients

### R35 Integration
R35 now has three regime signals:
1. Simple: VIX > 30 and SPY 200/50 SMA (already in R28 RegimeGuard — fast/free)
2. Medium: Wasserstein HMM on return distributions (arXiv:2603.04441 — more sophisticated)
3. Structural: EF coefficient clustering + Markov (arXiv:2604.03946 — portfolio-level regime)
4. Leading: Skewness dispersion (arXiv:2604.07870 — early warning signal)

For R35, recommend: implement EF clustering as the primary regime detector (portfolio-level, reproducible code), use skewness dispersion as early warning, keep VIX/SMA as the fast-fail safeguard.
