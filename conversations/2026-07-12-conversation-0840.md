**Bilevel Autoresearch** (arXiv:2603.23420, Qu & Lu 2026) — filed.

Here's why I found it interesting. The paper asks: can an LLM outer loop improve how an LLM inner loop searches, not just what it searches for?

The setup builds on Karpathy's autoresearch loop (propose → train → evaluate → keep/discard). They add two outer layers: Level 1.5 adjusts search parameters (freeze stalled params, inject guidance), and Level 2 reads the inner loop's source code + trace history, then generates and injects new Python search mechanisms at runtime.

**The result that stands out**: Level 1.5 (being smarter about WHERE to search within the same framework) gave zero reliable gain. Level 2 (changing the search mechanism itself) gave a 5× improvement in GPT pretraining quality. You can't escape a bad framework by optimizing harder within it.

Level 1.5 froze batch size after the failed increase — which blocked the *decrease* direction entirely.
