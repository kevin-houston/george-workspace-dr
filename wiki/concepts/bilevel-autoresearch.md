# Bilevel Autoresearch

**Paper**: "Bilevel Autoresearch: Meta-Autoresearching Itself" (Qu & Lu, 2026)
**arXiv**: 2603.23420 (v2 Jun 2026)
**Code**: github.com/EdwardOptimization/Bilevel-Autoresearch

A bilevel framework in which an outer LLM loop optimizes the search mechanism of an inner LLM autoresearch loop — not just what to search, but *how to search*.

---

## Core Idea

Autoresearch systems (Karpathy 2026, AutoResearchClaw, EvoScientist) run a loop:
- LLM proposes a change → execute → evaluate → keep/discard

These loops use **human-designed search procedures**. The key insight: can an LLM autonomously improve that procedure itself?

**Bilevel Autoresearch** adds an outer loop that reads the inner loop's source code and trace history, identifies bottlenecks, and generates injectable Python mechanisms at runtime. The result is a two-level optimization:

- **Inner level (Level 1)**: Optimize the task (e.g., GPT training configuration)
- **Outer level (Level 2)**: Optimize *how the inner level searches*

Both levels use the same LLM model. The gain comes from the bilevel architecture, not a stronger meta-level model.

---

## Three-Level Architecture

```
Level 2: Mechanism Research (every 2 outer cycles)
  ↓ reads code + trace → generates Python mechanism → inject
Level 1.5: Strategy Adjustment (every 5 inner iters)
  ↓ freeze stalled params → inject guidance string
Level 1: Inner Autoresearch Loop
  propose → train (300s budget) → evaluate val_bpb → keep/discard
```

### Level 1: Inner Loop
- Standard Karpathy autoresearch cycle
- 30 iterations, 300-second training budget per iteration
- Proposes hyperparameter changes to GPT pretraining config

### Level 1.5: Strategy Adjustment
- Executes every 5 inner iterations
- Can freeze over-explored parameters, redirect to under-explored ones
- Cannot change proposal logic, acceptance criterion, or loop structure
- **Cannot escape the structural search framework**

### Level 2: Mechanism Research (the key contribution)
Runs a 4-round structured dialogue:
1. **Explore** — LLM surveys mechanisms from adjacent fields (combinatorial opt, MAB, DOE, Bayesian opt)
2. **Critique** — selects most promising mechanism for observed failure mode
3. **Specify** — writes interface spec (class, methods, integration points)
4. **Generate** — writes runnable Python code implementing the mechanism

Generated code is injected via `importlib` dynamic loading with validate-and-revert:
- Import succeeds → patched runner replaces active one
- Import fails → original restored from backup

## Experimental Results (Karpathy GPT Benchmark)

**Task**: GPT pretraining (50M params), RTX 5090, fixed 300s training budget, 30 inner iterations.
**Metric**: Δ val_bpb (best – baseline, more negative = better).

| Group | Active Levels | Mean Δ ± Std | vs Group A |
|-------|-------------|------------|-----------|
| A | Level 1 only | −0.009 ± 0.002 | baseline |
| B | Level 1 + 1.5 | −0.006 ± 0.006 | no reliable gain |
| C | Level 1 + 1.5 + 2 | **−0.045 ± 0.030** | **5× improvement** |
| D | Level 1 + 2 | −0.034 ± 0.031 | 3.8× improvement |

**Key finding**: Level 1.5 (strategy adjustment) adds **no reliable gain** over Level 1. Level 2 (mechanism injection) produces a **5× improvement**. You cannot escape the structural search framework by being smarter within it — you need to change the mechanism itself.

## Mechanisms Generated by Level 2

| Mechanism | Domain | Active | Notes |
|-----------|--------|--------|-------|
| Tabu Search Manager | Combinatorial opt | ✓ | Prevents revisiting recent parameter regions |
| Multi-Scale Bandit Proposer | Online learning / MAB | ✓ | Exploration/exploitation balance across params |
| Systematic Orthogonal Exploration | Design of Experiments | ✓ | Forces orthogonal dimensional diversity |
| GP Regressor | Bayesian optimization | ✗ | Reverted — sklearn not installed |

All code generated on first attempt (zero retries). The LLM was told which adjacent *domains* to consider but not which specific mechanism to implement.

## The Core Discovery: TOTAL_BATCH_SIZE

The decisive finding across Level 2 conditions: **reducing TOTAL_BATCH_SIZE from 2^19 to 2^17–18 gave 5–8× larger improvements** than any other change.

Why it worked: smaller batch → more gradient steps within the fixed 300s budget on RTX 5090 (which runs SDPA, not Flash Attention 3). The original benchmark was tuned for H100.

Why Groups A and B missed it: DeepSeek has an implicit "larger batch is better" prior. Group A repeatedly tries to increase batch size and fails. Group B's Level 1.5 freezes TOTAL_BATCH_SIZE *after* the failed increase — blocking the decrease direction entirely.

Only the Tabu Search (which prevents revisiting failed directions) and Orthogonal Exploration (which forces dimensional diversity) led the inner loop toward decreasing batch size.

**The LLM prior problem**: LLMs have systematic biases in their search paths. Level 1.5 can redirect within the existing framework but cannot escape the bias. Level 2 changes the mechanism that generates proposals — which breaks the systematic bias.

## Mechanism Carriers — The Broader Frame

Code is not the privileged self-improvement artifact. Code is one *carrier* of a modifiable mechanism. Other carriers that change future agent behavior:

- **Skills** — reusable procedural policies
- **Prompts** — change the proposal prior
- **Workflows** — change control flow among tools/sub-agents
- **Evaluators** — change which candidates survive selection
- **Scientific principles / world-model assumptions** — change hypothesis space
- **Memory schemas** — change what state is available to future proposals

The key question is not "what artifact?" but "does it change the proposal, evaluation, selection, or update logic of the agentic loop?"

## Limitations

- **n=3 repeats per group** — statistically underpowered. Group C std dev is 67% of its mean.
- **Single benchmark** — one GPT task, one GPU family. Generalization unproven.
- **Prompt-induced domain bias** — Level 2 prompt suggests specific adjacent domains; constrains discoverable mechanisms to what the prompt author anticipated.
- **No stability guarantee** — runtime injection can produce brittle patches, evaluator overfitting. Only import validation and revert-on-failure, no formal convergence guarantee.
- **External dependency exposure** — Level 2 can import arbitrary libraries; one mechanism reverted due to missing sklearn.
- **Recursive claim is unproven** — the paper demonstrates Level 2 improves Level 1, but does not show that the same principle improves Level 2. Recursive bootstrapping is "a path, not a completed result."

## Relevance to Our Stack

**High relevance** — multiple connection points:

### Dream Cycle Connection
The dream cycle IS an autoresearch loop: it proposes hypotheses (analogous to proposing hyperparameter changes), stages them, applies them, and evaluates. A bilevel extension could:
- **Level 2 outer loop**: Read the dream cycle's staging history, identify systematic biases in what kinds of hypotheses get proposed, generate new staging/proposal mechanisms (e.g., "generate at least one microstructure hypothesis per scan," "force OOS split variation," "propose cross-asset analog of every confirmed equity hypothesis")
- This would directly address any "LLM prior" in the hypothesis generation pattern

### H381 / H382 / H274 (Multi-Agent Trading)
- H381 AlphaLogics uses a 3-agent loop (Analyst→Coder→Critic). A bilevel layer could improve that loop's search strategy rather than just its outputs.
- H274 multi-agent PEAD upgrade: the 3-agent debate structure could benefit from a Level 2 mechanism that detects repetitive debate patterns and injects diversity.

### Alpha Illusion Checklist Connection
The "LLM prior problem" is directly analogous to why the Alpha Illusion checklist exists: LLMs have systematic biases toward producing certain kinds of results. Level 2 mechanism injection is one architectural solution to breaking those biases.

### ATLAS Tool (wiki/trading/tools/atlas-gic.md)
ATLAS explicitly references Karpathy autoresearch and uses a 4-layer 25-agent architecture. Bilevel Autoresearch is the formal framework behind ATLAS's JANUS meta-layer concept.
