## New content: idempotency & concurrency control for scheduled trading automation

New page `paper-trading/idempotency-concurrency-control.md`. Rather than a generic
scheduling-theory page, grounded the topic directly in this project's own operational
history: `.local-fragments/task-registry.md` documents at least four distinct
duplicate-execution races this year (PEAD-GAP open-pass 4x-in-65-seconds on 2026-07-31,
dream-cycle build-phase double wiki-append on 2026-08-01, two separate git add/commit
sweep incidents on 2026-08-03, the podcast-script near-miss on 2026-08-12). All share the
same root cause — at-least-once trigger delivery with no designed exclusivity guard around
the side-effecting work — so researched the concrete library-level fix rather than the
incident pattern (already well documented elsewhere).

Landed on `filelock` (PyPI, 975★ GitHub, MIT, actively maintained — v3.32.3 as of
2026-08-13) as the right-weight solution: this project runs single-container Python
scripts writing local JSON/log files, not a distributed fleet, so a plain advisory file
lock via `fcntl.flock`/`msvcrt` fits better than Redis or Postgres distributed locking
(covered as reference-only, explicitly flagged as not needed at current scale). Also
documented APScheduler's `max_instances`/`coalesce`/`misfire_grace_time` as the
scheduler-level reference design, and the cheaper idempotency-key check-before-write
pattern this project already partially uses (dream_cycle staged-dir checks, podcast
`ls`-before-generate checks) — with the 2026-08-12 podcast race as a worked example of
where a single check-at-start isn't sufficient and a second guard (or the Write tool's
built-in read-before-write enforcement) is needed.

Proposed concrete next step (not implemented tonight, staged as a dream-cycle proposal):
retrofit `FileLock` into `pead_open.py`, `pead_exits.py`, `pead_gap_open.py`,
`pead_gap_exits.py`, and the dream-cycle build phase — the highest-cost scripts when the
current incidental guards fail (real order submission / destructive double-append).
`filelock` is not yet in `venv/`; per standing package-installation policy, did not
install it during this off-hours session — verified PyPI existence/reputation only.
