### Vectorbt H-series implementation

Key finding: implementing cross-sectional momentum rotation in Vectorbt requires three non-obvious settings working together:

```python
pf = vbt.Portfolio.from_orders(
    close=close_df,
    size=alloc,             # NaN except on rebalance dates
    size_type='targetpercent',
    group_by=True,          # treat all assets as one portfolio
    cash_sharing=True,      # pool cash across positions
    call_seq='auto',        # CRITICAL: sell before buy
)
```

**`call_seq='auto'`** is the most important and least documented requirement. Without it, Vectorbt tries to buy before selling, fails on insufficient cash, and silently produces wrong results. `group_by=True` and `cash_sharing=True` are also required for true multi-asset rebalancing.

**Allocation array pattern**: only fill `alloc[i, :]` on rebalance dates (first trading day of each month); leave NaN on all other rows. Vectorbt interprets NaN as "hold current position."

## Session 4 complete: Kalshi API deep dive

### Authentication

RSA-PSS is the only supported auth method (not simple API keys). Key setup:
- Generate 2048-bit RSA key pair in Kalshi dashboard
- **Cannot retrieve private key after creation** — store immediately
- Signature = RSA-PSS-SHA256 of `timestamp_ms + HTTP_METHOD + url_path`
- Set as env vars: `KALSHI_API_KEY_ID` + `KALSHI_PY_PRIVATE_KEY_PEM`

### API structure

Two clean tiers:
1. **Public endpoints** (no auth): `/markets`, `/markets/{ticker}`, `/markets/{ticker}/orderbook`, candlesticks, trades
2. **Authenticated endpoints**: `/portfolio/balance`, `/portfolio/positions`, `/portfolio/orders` (CRUD)

Order parameter gotcha: `yes_price` takes integer cents (1–99), NOT decimal probability. Always multiply by 100.

### WebSocket streaming channels

8 available channels; the key ones for algo trading:
- `orderbook_delta` — incremental book (required for fast arbitrage)
- `ticker` — best bid/ask/last/volume
- `fill` — your executed fills (auth required)
- `market_lifecycle_v2` — market settlement events

### Fee modeling

The fee formula `0.07 × C × P × (1 − P)` peaks at $0.50 (50¢ contracts = maximum fee). Key implication: strategies trading near-extreme probabilities (e.g., 10¢ or 90¢) pay ~64% less in fees. Maker orders (limit orders) are 4× cheaper than takers — prefer limit when latency allows.

**Fee calculation matters**: a 3% edge at $0.50 with 100 contracts costs $1.75 in taker fees — model fees explicitly in position sizing.

### CPI nowcasting implementation

Full end-to-end code added:
1. Pull FRED CPI + PCE data via `fredapi`
2. ARIMA(2,0,1) baseline on last 36 months of MoM changes
3. Ensemble with PCE nowcast (70/30 blend)
4. Convert to probability with `scipy.stats.norm.cdf`
5. Kelly-size position: quarter-Kelly, `f* = (p × M − (1−p)) / (M − 1)`
6. Fee check: only trade if net edge after fees > 0.5%
7. Submit via `kalshi-py` SDK with `immediate_or_cancel` TIF

The IOC order type is important — old limit orders priced before a data revision shouldn't sit in the book.
