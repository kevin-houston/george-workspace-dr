## New content: tools/backtest-bias.md

New tools page on **backtest-bias** (Ayan Jain / Finance-broski, PyPI `backtest-bias`,
GitHub github.com/Finance-broski/backtest-bias, MIT, Zenodo DOI 10.5281/zenodo.21770386,
v0.2.0 released 2026-08, 11★ — small/single-author but legitimate: consistent identity
across PyPI/GitHub/LinkedIn/Substack, `CITATION.cff`, zero open issues, no hallusquatting
signals per the standing package-verification policy — not installed, reference only).

- **What it does**: automated integrity checks on a price panel — `check_survivorship`,
  `dead_name_ratio`, `assert_integrity` (v0.1); `check_identity` (recycled-ticker
  detection) and `check_universe` (index-membership-applied-backwards detection) new
  in v0.2. Returns a severity verdict plus a *measured* bias-magnitude estimate rather
  than a bare boolean.
- **Measured constants**: +0.8-3.2pp/yr EW-return inflation from survivor-only universes
  (Indian equities); +0.4-1.0pp/yr survivor-filter effect (US, newer/thinner sample);
  1.7pp/yr swing from a ticker-identity error (4 recycled tickers in one measured case)
  — larger than the survivorship effect itself in that instance; death-rate curve
  benchmark (~5-8% dead by 3yr, 24-30% by 10yr) to sanity-check whether a panel's own
  death count looks survivor-contaminated.
- **Why it matters here**: `backtesting/survivorship-bias.md` already covers the
  mechanism and a manual point-in-time universe builder in depth, but every H24x-family
  survivorship verdict in this wiki has been argued qualitatively ("large caps rarely
  delist mid-index") rather than measured against the actual cached price panel in
  code. This library is a direct, low-effort fit for turning that into a quantified
  check. Cross-linked into `survivorship-bias.md`.
- **Notable roadmap item (v0.3, not yet shipped)**: fundamentals dated by period
  instead of announcement date, index membership applied backwards, same-bar signal
  fills — structurally the same as-of-date look-ahead bug class as this project's own
  H509-H514 corrections (OB/FVG filter `as_of` bug, PEAD `skip=0` signal-endpoint bug).
  Flagged to re-check once v0.3 lands as a possible mechanical pre-backtest gate,
  complementary to (not a replacement for) manual `as_of` audits.

No hypothesis proposed from this alone — it's a tooling/methodology find, not a new
signal. Logged as a candidate integration for the backtest-hygiene toolchain.
