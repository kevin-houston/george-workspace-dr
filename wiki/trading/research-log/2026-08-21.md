## New content: tools/pybroker.md — edtechre/pybroker

New page on **PyBroker** (edtechre/pybroker, 3.5k★, Apache 2.0 with Commons
Clause, PyPI package name `lib-pybroker` — not `pybroker`, flagged explicitly
to avoid a future install mistake). NumPy/Numba-accelerated backtester built
for ML-driven strategies, with two features that map directly onto open gaps
in our own process rather than being generically interesting:

- **BCa bootstrap confidence intervals on Sharpe and Profit Factor**, resampled
  per-bar (not per-trade, which would understate uncertainty when trades
  cluster). Every `run_hNNN.py` currently reports a single point-estimate OOS
  Sharpe against a fixed gate — a hypothesis clearing 1.174 by a hair and one
  clearing it by a full point are logged as equally "CONFIRMED" today, with no
  sense of how much of the gap between the two is noise.
- **Walkforward Analysis as a first-class primitive** — rolling train/test
  windows with retraining at each step, vs. our single-cut IS/OOS split. Would
  have surfaced regime-dependent overfitting (the H435-H437 "H026 canonical OOS
  degrading 2024-2026" pattern) more systematically than a single split.

Explicitly scoped what it does *not* solve: neither feature is a look-ahead-
bias detector — it would not have caught the `as_of`-date bug family
(H510-H514, H343-H346, H355-H356), which needs the manual "does this function
receive a future date" audit already established for that correction chain.
Page also captures a minimal working rule-based code example (Strategy/
StrategyConfig/YFinance/ctx.buy_shares pattern) and a relevance table vs.
qf-lib (options/event-driven remains qf-lib's lane, not PyBroker's).
