## What was found (WebSearch + WebFetch: docs.alpaca.markets, alpaca.markets/support, github.com/alpacahq/alpaca-py)

Alpaca has supported **multi-leg (mleg) Level 3 options orders in paper trading since January 2025** — confirmed via Alpaca's own changelog and X/Twitter announcement, so this capability has been available for the entire time the wiki's iron condor design has existed; it just wasn't documented in the wiki.

Key mechanics (from `docs.alpaca.markets/docs/options-orders`, `docs.alpaca.markets/docs/options-level-3-trading`):
- `order_class="mleg"` + a `legs` array of `OptionLegRequest(symbol, side, ratio_qty)`, 2-4 legs per order, submitted and filled atomically
- `ratio_qty` must be GCD-simplified across all legs (no common divisor > 1)
- Margin computed via a "universal spread rule" — `cost_basis = maintenance_margin + (net_price × multiplier)` on the combined position, not the sum of each leg's independent margin, so a defined-risk iron condor needs far less buying power than 4 naked legs
- Paper accounts get Level 3 by default with no application; live accounts need a separate Apex Clearing approval step
- Assignment/exercise: Alpaca auto-exercises ITM at expiry, auto-closes if buying power is insufficient, and assignment events are **not** pushed via WebSocket — must poll REST

Pulled the actual working Python code from Alpaca's own `alpacahq/alpaca-py` repo (`examples/options/options-iron-condor.ipynb`, fetched via raw.githubusercontent.com and parsed as JSON) — a real, runnable 4-leg short iron condor submission using `OptionLegRequest` + `MarketOrderRequest(order_class=OrderClass.MLEG, legs=order_legs)`. Included verbatim in the wiki update with a caution about using `limit_price` instead of a bare market mleg order on wide/illiquid 0DTE strikes.
